=== CONTENT ===
Speculative Decoding — Summary

- **How it works:** Speculative decoding speeds up autoregressive inference by having a cheap draft mechanism propose several tokens that the target model verifies in a single batched forward pass; accepted tokens reach large-model quality at near draft-model cost, a rejection truncates the proposal and the target resumes from the last accepted token, and outputs stay distributionally identical to standard decoding. Drafts can be a separate small model, an n-gram lookup over the prompt and generation history, or a jointly trained multi-token-prediction (MTP) head that predicts a short future window from the same hidden state as the target.
- **Economics depend on workload:** Code and structured text repeat long spans, so n-gram drafting accepts many tokens almost for free, while open-ended prose accepts fewer and a poorly matched draft can make generation slower than running the target alone because each rejected batch wastes a full verification pass.
- **MTP heads sit in between:** They add only a little memory and compute per step, but their acceptance rates stay stable across domains because the head sees the exact context the target sees.
- **MoE models complicate the picture:** An MoE layer routes each token to only a subset of experts, so active parameter counts are a fraction of the total and decoding can be fast even on integrated GPUs; but speculative verification batches several positions together, and since each may route to different experts, it pulls more expert weights through memory per step—on bandwidth-bound hardware this erodes the batching advantage and raises the break-even acceptance rate above that for dense models.
- **Server-side parallelism interacts with all of it:** Slot-based servers split the KV-cache budget across concurrent sequences—more slots raise aggregate throughput but lower per-stream speed—and speculation competes with extra slots for the same compute headroom, so speculative mode, slot count, and sampling must be tuned as one joint configuration and evaluated by end-to-end tokens per second on representative tasks rather than microbenchmarks.

**TL;DR:** Speculative decoding gains come from cheap draft proposals batch-verified by the target, but how much they help depends on the workload's acceptance rate, the memory routing of MoE experts, and how they trade off against server slots—so it must be tuned and measured end-to-end as one joint configuration.
