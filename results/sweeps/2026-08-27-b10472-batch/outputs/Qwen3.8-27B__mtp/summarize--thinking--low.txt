=== CONTENT ===
- **Mechanism & guarantee:** Speculative decoding lets a cheap draft mechanism propose several tokens that the target model verifies in a single batched forward pass; accepted tokens come out at large-model quality for near draft-model cost, and a rejection truncates the proposal with the target resuming from the last accepted position, keeping outputs distributionally identical to standard decoding.
- **Draft options:** The draft can be a separate small model, an n-gram lookup over the prompt and generation history, or—per newer designs—a multi-token-prediction (MTP) head trained jointly with the target that predicts a short window of future tokens from the same hidden state.
- **Workload economics differ:** Code and structured text repeat long spans so n-gram drafting reaches high acceptance rates almost for free; open-ended prose accepts fewer speculative tokens, and a poorly matched draft model can make generation slower than the target alone because each rejected batch wastes a full verification pass; MTP heads sit in between, adding small per-step memory/compute while tending toward stable cross-domain acceptance because the head sees the exact context the target sees.
- **MoE complicates the picture:** Because an MoE layer routes each token to a small subset of experts, active per-token parameters are a fraction of the total—enabling fast decode of tens-of-billions-parameter models on integrated GPUs with unified memory—but speculative verification batches positions that may route to different experts, pulling more expert weights through memory per step; on bandwidth-bound hardware this erodes the batching advantage and raises MoE targets' break-even acceptance rate above dense ones'.
- **Server-side interaction:** Slot-based servers split the KV-cache budget across concurrent sequences, so more slots raise aggregate throughput but lower per-stream speed, and speculation competes with extra slots for the same compute headroom; tuning must therefore treat speculative mode, slot count, and sampling settings as one joint configuration and measure end-to-end tokens per second on representative tasks rather than trusting microbenchmarks.

**TL;DR:** Speculative decoding can match standard decoding's outputs at lower cost, but whether it actually pays off depends on the workload, on dense-versus-MoE target architecture, and on how speculative mode is jointly configured with server slot allocation—so it must be tuned and validated end to end rather than assumed universally beneficial.
