=== CONTENT ===
- Speculative decoding accelerates autoregressive inference by using a draft mechanism—such as a small separate model, an n-gram lookup over prompt history, or a jointly trained multi-token-prediction (MTP) head—to propose tokens that the target model verifies in a single batched forward pass.
- Tokens accepted by the target model retain large-model quality at near draft-model cost, while rejections truncate the proposal and cause the target to resume from the last accepted position, ensuring outputs remain distributionally identical to standard decoding.
- Drafting approaches differ economically by workload: n-gram drafting achieves high acceptance rates almost for free on code and structured text with long repeating spans, whereas open-ended prose accepts fewer tokens and a poorly matched draft model can slow generation compared to running the target alone due to wasted verification passes on rejected batches; MTP heads offer stable acceptance rates across domains with small per-step memory and compute overhead because they see the same context as the target.
- For mixture-of-experts (MoE) target models, speculative verification’s batching advantage erodes on bandwidth-bound hardware because each position may route to different experts, pulling more expert weights through memory per step and thus requiring a higher break-even acceptance rate than for dense models.
- Server-side parallelism via slot-based KV-cache splitting means speculation competes with extra slots for the same compute headroom, so tuning speculative mode, slot count, and sampling settings as one joint configuration and measuring end-to-end tokens per second on representative tasks is essential rather than relying on microbenchmarks.

TL;DR: Speculative decoding accelerates autoregressive inference when the draft mechanism’s acceptance rate is high enough to offset verification costs, but its effectiveness varies by workload type, target model architecture (dense vs MoE), and server-side parallelism configuration.
