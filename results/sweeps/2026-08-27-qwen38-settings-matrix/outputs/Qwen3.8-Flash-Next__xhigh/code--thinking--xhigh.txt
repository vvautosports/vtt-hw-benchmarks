```python
import re

_RANGE_RE = re.compile(r"^(?P<lo>[-+]?\d+)\s*-\s*(?P<hi>[-+]?\d+)$")
_NUMBER_RE = re.compile(r"^[-+]?\d+$")


def parse_ranges(s: str) -> list[int]:
    r"""Parse a range expression such as ``'1-3,5,7-9'`` into a list of ints.

    The input is a comma-separated list of single integers and inclusive
    ``start-end`` ranges, expanded in the order they appear. Whitespace around
    numbers, around the dash and around commas is ignored. An empty (or
    whitespace-only) string yields an empty list. Duplicates and overlaps are
    kept exactly as written; the result is neither sorted nor de-duplicated.

    Args:
        s: The expression to parse, e.g. ``"1-3, 5 , 7-9"``.

    Returns:
        The expanded list of integers.

    Raises:
        ValueError: If a part is malformed (empty or non-numeric) or if a range
            runs backwards, i.e. its start is greater than its end.

    Examples:
        >>> parse_ranges("1-3,5,7-9")
        [1, 2, 3, 5, 7, 8, 9]

        Whitespace around numbers, dashes and commas is ignored:
        >>> parse_ranges("  1 - 3 ,  5 ,7-  9  ")
        [1, 2, 3, 5, 7, 8, 9]

        Empty or whitespace-only input returns an empty list:
        >>> parse_ranges("")
        []
        >>> parse_ranges("   \t\n ")
        []

        Order is preserved; a single-value range collapses to one item:
        >>> parse_ranges("10, 3-4, 1, 6-6")
        [10, 3, 4, 1, 6]

        Negative endpoints work too:
        >>> parse_ranges("-2--1, 0")
        [-2, -1, 0]

        A reversed range raises ValueError:
        >>> parse_ranges("9-7")
        Traceback (most recent call last):
            ...
        ValueError: reversed range: '9-7'

        Malformed parts raise ValueError as well:
        >>> parse_ranges("1-3,,5")
        Traceback (most recent call last):
            ...
        ValueError: empty part in '1-3,,5'
        >>> parse_ranges("1-a")
        Traceback (most recent call last):
            ...
        ValueError: invalid number: '1-a'
    """

    def as_int(token: str) -> int:
        token = token.strip()
        if not _NUMBER_RE.match(token):
            raise ValueError(f"invalid number: {token!r}")
        return int(token)

    if not s.strip():
        return []

    numbers: list[int] = []
    for part in s.split(","):
        part = part.strip()
        if not part:
            raise ValueError(f"empty part in {s!r}")
        match = _RANGE_RE.match(part)
        if match:
            lo, hi = int(match["lo"]), int(match["hi"])
            if lo > hi:
                raise ValueError(f"reversed range: {part!r}")
            numbers.extend(range(lo, hi + 1))
        else:
            numbers.append(as_int(part))
    return numbers


if __name__ == "__main__":
    import doctest

    doctest.testmod()
```

Notes on the design choices worth flagging:

- **Regex-matched ranges instead of `part.split("-")`** — this is what makes `-2--1` parse as a range from −2 to −1 rather than blowing up, and it rejects garbage like `1-2-3`, `3-`, or `-` with `invalid number: ...`.
- **Whitespace-only returns `[]`**, but a stray comma (`"1-3,"` or `"1,,2"`) raises `ValueError`, since silently dropping an empty part is usually hiding a typo. Say the word if you'd rather it be lenient.
- **Output order/payload preserved** — no sorting, no dedup, so `10, 3-4, 1` → `[10, 3, 4, 1]`. Easy to change to `sorted(set(numbers))` if you want a normalized set instead.
- Error messages quote the offending part (`'9-7'`) rather than just the number, which makes them much more useful when the input is long.
