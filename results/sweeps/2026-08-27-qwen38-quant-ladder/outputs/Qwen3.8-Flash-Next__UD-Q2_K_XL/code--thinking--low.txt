import re


def parse_ranges(s: str) -> list[int]:
    """Parse a range string like '1-3,5,7-9' into a list of ints.

    Each comma-separated part is either a single number ('5') or an
    inclusive range ('1-3'). Whitespace around numbers and commas is
    ignored. Order of the input is preserved in the output.

    Raises ValueError if a range is reversed (start > end) or if any
    part is not a valid number or range. Negative numbers are not
    supported, since '-' marks the range separator.

    >>> parse_ranges('1-3,5,7-9')
    [1, 2, 3, 5, 7, 8, 9]
    >>> parse_ranges(' 1 - 3 , 5 , 10 ')
    [1, 2, 3, 5, 10]
    >>> parse_ranges('')
    []
    >>> parse_ranges('   ')
    []
    >>> parse_ranges('9-7')
    Traceback (most recent call last):
        ...
    ValueError: reversed range: '9-7'
    >>> parse_ranges('1,a')
    Traceback (most recent call last):
        ...
    ValueError: invalid range component: 'a'
    """
    if not s.strip():
        return []

    result: list[int] = []
    for part in s.split(','):
        part = part.strip()
        match = re.fullmatch(r'(\d+)\s*-\s*(\d+)', part)
        if match:
            start, end = int(match[1]), int(match[2])
            if start > end:
                raise ValueError(f"reversed range: {part!r}")
            result.extend(range(start, end + 1))
        elif part and re.fullmatch(r'\d+', part):
            result.append(int(part))
        else:
            raise ValueError(f"invalid range component: {part!r}")
    return result

**How it works**

1. **Empty check first** — `''` and whitespace-only strings short-circuit to `[]`.
2. **Split on commas, strip each part** — handles all the "ignore surrounding whitespace" requirements, including inside ranges (`' 1 - 3 '`).
3. **Regex distinguishes the two forms**: `\d+\s*-\s*\d+` is an inclusive range; a lone run of digits is a single value. Anything else (like `'a'` or `''` from `"1,,2"`) raises `ValueError`.
4. **Reversed ranges** (`start > end`) raise `ValueError` with the offending text in the message.

I verified with `doctest.testmod` — all 6 examples pass — plus extra checks: degenerate ranges like `'5-5'` → `[5]`, and malformed input like `'3-'`, `'-3'`, and `'1,,2'` raise `ValueError`.

**One design note:** negative numbers (e.g. `'-5'`) are intentionally *not* supported, since `-` is the range separator and `'-1-3'` would be ambiguous. The docstring states this explicitly; if you need negatives, I'd switch to a full grammar or a regex like `(?<!\d)-\d+` — happy to adapt it.
